# Secret JSON keys (names only)

Secret `<name_prefix>/hackathon` (Secrets Manager, one secret, JSON object). Values are set out of band; Terraform seeds
`CHANGE_ME` (and the random `RDS_MASTER_PASSWORD`) and ignores later changes. Names marked (assumed) were not confirmed
with the owning team: they are module variables.

| Workload | Keys |

Setting a value: never paste a secret into chat, a file or a command line. Run `.\scripts\aws-prod.ps1 set-secret -Profile pulso-prod -SecretKey GATEWAY__OPENROUTER_API_KEY`: it prompts for the value without echo, merges that one key into `pulso-prod/hackathon` (every other key is kept), and prints and logs nothing but the key name. It refuses an empty value and `CHANGE_ME`, accepts only `<SERVICE>__<VAR>` keys with SERVICE in `COMMON, CORE, GATEWAY, SUPPORT, PULSO`, and asks for the word SET. The value passes through a temp file outside the repository that is deleted immediately. Hosts read the new value at the next `pulso-stack` restart or deploy.

LLM routing: the gateway alias is the endpoint name (for example `openrouter`, whose key variable `OPENROUTER_API_KEY` comes from `GATEWAY__OPENROUTER_API_KEY`). The model `deepseek/deepseek-v4.1-flash` is set in the caller profile of the calling service, not in the gateway.

Host-consumed keys are `<SERVICE>__<VAR>`: the compute start script writes `<VAR>` into `/run/pulso/env/<service>.env` for the services of its own host (`CORE`, `GATEWAY` on the core host, `SUPPORT` on the platform host, `PULSO` on the engine host, `COMMON` on all). `DB_PASSWORD_*` and `RDS_MASTER_PASSWORD` carry no prefix and are never rendered into an env file. All three hosts can read the whole secret (one secret, one ARN): the prefix selects what a host renders, it is not an access boundary.

Non-secret configuration is in SSM Parameter Store (standard tier, free) under `/pulso/<workload>/<service>/<NAME>` (workload `core|platform|engine`, service `core|gateway|support|pulso|common`; each host role reads only `/pulso/<its workload>/*`):
agent-core `AGENTCORE_DAILY_BUDGET_USD`, `AGENTCORE_TOOL_SERVICE_URL` (out of band; no tool service is deployed yet),
`AGENTCORE_BLOB_BUCKET` (derived `s3://<bucket>/core/blobs`, overridden by the compose bucket name and prefix), `AGENTCORE_SERVE_AGENTS` (derived); the
legacy `PULSO_LAB_BROKER_URL`, `PULSO_CONTROL_API_URL`, `PULSO_TENANT_ID` placeholders are unused (ADR 0009) and kept only so an apply destroys nothing;
llm-gateway `GATEWAY_CONSUMERS` and `LLM_ENDPOINTS` (derived: consumers `agent-core`, `engine`, `support-platform`, endpoint `openrouter`);
engine `PULSO_CORE_KID` (derived `pulso-engine-<agent_keys_suffix>`), `PULSO_CORE_PRINCIPAL_ID` (`builder`), `PULSO_LLM_GATEWAY` (`enabled`);
support-platform `CC_CORS_ORIGINS`, `CC_PUBLIC_APP_URL`; engine `PULSO_DATA_MODE`, `PIPELINE_ROOT` (derived
`s3://<bucket>/lake`).

Host grant: `secretsmanager:GetSecretValue` on the single `secret_arn` output, and `ssm:GetParameter*` on
`ssm_parameter_arn_prefix/*`. The secret uses the AWS managed key `aws/secretsmanager` (no extra KMS cost). The data KMS key encrypts the S3 objects; the host roles hold `kms:Decrypt` and `kms:GenerateDataKey` on it.

## Generated by Terraform (ADR 0009)

`random_password` (gateway bearers, grant-check bearer), `random_bytes` (the Core's HMAC key material) and `tls_private_key` (four Ed25519 keys: platform
principal, delegation and staff, and the engine) seed the secret once, like `COMMON__ORIGIN_VERIFY`. The secret version ignores later changes, so an apply
never rotates them and never overwrites a value set out of band. The state holds them in clear (the state bucket is the protection, as for the RDS password).

- **Formats.** `CORE__IDENTITY_KEYS_JSON` is agent-core's `--identity-keys` file (`principal_keys` = platform principal key + engine key, `delegation_keys` = platform
  delegation key); `CORE__STAFF_KEYS_JSON` is `--staff-keys` (`principal_keys` = platform staff key + engine key). `SUPPORT__AGENT_KEYS_JSON` is the platform's
  `CC_AGENT_KEYS_FILE` (`principal`/`delegation`/`staff` with `kid` and `seed`). `PULSO__PULSO_CORE_SIGNING_SEED` is the engine's 32-byte Ed25519 seed (base64url, no padding).
  Key ids: `cc-principal-<s>`, `cc-grant-<s>`, `cc-staff-<s>`, `pulso-engine-<s>` with `<s>` = `agent_keys_suffix` (default `hk1`). The compose entrypoints write the
  JSON documents to `/tmp` inside the containers before the service starts.
- **Engine credentials.** One key, three claims: `builder` principal for `/v1/runs` (identity-keys), non-human `builder` with role `constructor` for `/v1/registry/*`
  and with role `exporter` for `/v1/export/runs` and `/registry-events` (staff-keys). The engine mints each credential with the claims it needs; it never signs
  `aprobador`, never approves, publishes or promotes. Public half: `terraform output engine_core_public_key` (also `engine_core_kid`).
- **Trust.** Any key in `staff-keys` can claim any role (agent-core checks the claimed roles, not a per-key ceiling). Treat the engine key as a trust grant.
- **Derivation check.** The Ed25519 seed and public key are cut out of the provider's PKCS#8 and SPKI PEM (fixed prefixes) in pure HCL; `hackathon_data.tftest.hcl` pins the
  result against RFC 8032 test vector 1. Re-run `terraform test` in `terraform/modules/hackathon_data` after any change to `generated.tf`.
- **Existing secret.** If `pulso-prod/hackathon` already exists, an apply creates the generated resources and changes nothing in it. To seed it, either (a) before any
  out-of-band value matters, `terraform apply -replace=module.data.aws_secretsmanager_secret_version.this` (resets every key to its placeholder or generated value, so
  re-run `set-secret` for the out-of-band keys afterwards), or (b) set each generated key by hand with `set-secret` (the value must come from you, not from this repository).
- **Rotation.** Publish a new `agent_keys_suffix` only together with a secret reseed (a), keep the old public keys in the Core files until the platform and the engine use the new
  ones (the Core re-reads its key files on a short interval but these files are written at container start: restart `core-runtime` after reseeding).
