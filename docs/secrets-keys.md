# Secret JSON keys (names only)

Secret `<name_prefix>/hackathon` (Secrets Manager, one secret, JSON object). Values are set out of band; Terraform seeds
`CHANGE_ME` (and the random `RDS_MASTER_PASSWORD`) and ignores later changes. Names marked (assumed) were not confirmed
with the owning team: they are module variables.

Setting a value: never paste a secret into chat, a file or a command line. Run `.\scripts\aws-prod.ps1 set-secret -Profile pulso-prod -SecretKey GATEWAY__OPENROUTER_API_KEY`: it prompts for the value without echo, merges that one key into `pulso-prod/hackathon` (every other key is kept), and prints and logs nothing but the key name. It refuses an empty value and `CHANGE_ME`, accepts only `<SERVICE>__<VAR>` keys with SERVICE in `COMMON, CORE, GATEWAY, SUPPORT, PULSO, AGENT, TOOLS, DB` (upper case) or `FILES__<AGENT|SUPPORT>__<NAME>`, and asks for the word SET. The value passes through a temp file outside the repository that is deleted immediately. Hosts read the new value at the next `pulso-stack` restart or deploy.

LLM routing: the gateway alias is the endpoint name (for example `openrouter`, whose key variable `OPENROUTER_API_KEY` comes from `GATEWAY__OPENROUTER_API_KEY`). The model `deepseek/deepseek-v4.1-flash` is set in the caller profile of the calling service, not in the gateway.

Host-consumed keys are `<SERVICE>__<VAR>`: the compute start script writes `<VAR>` into `/run/pulso/env/<service>.env` for the services of its own host (`CORE`, `GATEWAY` on the core host, `SUPPORT` on the platform host, `PULSO` on the engine host, `COMMON` on all). `DB_PASSWORD_*` and `RDS_MASTER_PASSWORD` carry no prefix and are never rendered into an env file. `FILES__<SERVICE>__<NAME>` keys are never env lines either: the start script writes each as the file `/run/pulso/files/<service>/<NAME>` (tmpfs, 0400, uid 10001), for values a service reads as a file (key sets, grants). All three hosts can read the whole secret (one secret, one ARN): the prefix selects what a host renders, it is not an access boundary.

Non-secret configuration is in SSM Parameter Store (standard tier, free) under `/pulso/<workload>/<service>/<NAME>` (workload `core|platform|engine`, service `core|gateway|support|pulso|common`; each host role reads only `/pulso/<its workload>/*`):
agent-core `PULSO_LAB_BROKER_URL`, `PULSO_CONTROL_API_URL`, `PULSO_TENANT_ID`, `AGENTCORE_DAILY_BUDGET_USD`,
`AGENTCORE_BLOB_BUCKET` (derived `s3://<bucket>/core/blobs`); llm-gateway `GATEWAY_CONSUMERS`, `LLM_ENDPOINTS`;
support-platform `CC_CORS_ORIGINS`, `CC_PUBLIC_APP_URL`; engine `PULSO_DATA_MODE`, `PIPELINE_ROOT` (derived
`s3://<bucket>/lake`).

Host grant: `secretsmanager:GetSecretValue` on the single `secret_arn` output, and `ssm:GetParameter*` on
`ssm_parameter_arn_prefix/*`. The secret uses the AWS managed key `aws/secretsmanager` (no extra KMS cost). The data KMS key encrypts the S3 objects; the host roles hold `kms:Decrypt` and `kms:GenerateDataKey` on it.

## Generated by Terraform (ADR 0009)

`random_password` (gateway bearers, grant and tool-service bearers), `random_bytes` (agent-core HMAC keys) and `tls_private_key` (four Ed25519 keys) seed
the secret once, like `COMMON__ORIGIN_VERIFY`. The secret version ignores later changes, so an apply never rotates them and never overwrites a value set out
of band. The state holds them in clear (the state bucket is the protection).

- Always: `GATEWAY__GATEWAY_TOKEN_<C>` for every consumer (`AGENT_CORE`, `AGENT_SERVE`, `ENGINE`, `SUPPORT_PLATFORM`), `CORE__AGENTCORE_LLM_GATEWAY_TOKEN`, `PULSO__PULSO_LLM_GATEWAY_KEY`, `PULSO__PULSO_SERVICE_SEED_HEX` (the engine's Ed25519 seed as 64 hex characters).
- With `agent_services_enabled`: `AGENT__AGENTCORE_LLM_GATEWAY_TOKEN`, `AGENT__AGENTCORE_GRANTS_TOKEN` and `SUPPORT__CC_INTERNAL_SERVICE_TOKEN` (one value), `AGENT__AGENTCORE_KEYS_FINGERPRINT`, `AGENT__AGENTCORE_KEYS_TOKEN_MAP`, `AGENT__AGENTCORE_TOOL_SERVICE_TOKEN` and `TOOLS__TOOL_SERVICE_TOKENS`, and the key documents `FILES__AGENT__IDENTITY_KEYS` (platform principal + delegation + engine key), `FILES__AGENT__STAFF_KEYS` (platform staff + engine key) and `FILES__SUPPORT__AGENT_PRIVATE_KEYS`.
- Key ids: `cc-principal-<s>`, `cc-grant-<s>`, `cc-staff-<s>`, `pulso-engine-<s>` with `<s>` = `agent_keys_suffix` (default `hk1`); SSM `PULSO_SERVICE_KID` carries the engine's. Public half: `terraform output engine_core_public_key`.
- Engine credentials: one key, three claims (non-human `builder`; `constructor` for `/v1/registry/*`, `exporter` for `/v1/export/*`). **Trust:** any key in staff-keys can claim any role, so this key can mint human credentials and approve or publish; "the engine never approves" is engine code discipline, and every host reads the whole secret including the platform staff seed. See ADR 0009 (accepted risk, owner sign-off).
- With `platform_database_enabled` ([shared-postgres](shared-postgres.md)): `DB__DB_PASSWORD_PLATFORM_OWNER`, `_PLATFORM_APP`, `_PLATFORM_EXPORTER_RO`, `_TOOLS_OWNER`, `_TOOLS_APP`, `SUPPORT__CC_MIGRATE_DATABASE_URL` (assumed name), `PULSO__PULSO_PG_PRODUCT_DSN` (out of band), and generated `PULSO__PULSO_PLATFORM_SERVICE_TOKEN` (equal to `SUPPORT__CC_INTERNAL_SERVICE_TOKEN`).
- Not generated (out of band): DSNs and migrate DSNs, `AGENT__AGENTCORE_JEV_API_KEY`, `FILES__AGENT__FIELD_GRANTS`, `FILES__AGENT__FIELD_OVERLAY`, `FILES__SUPPORT__BANK_CUSTOMER_LINKS`, provider keys, DB passwords.
- **Existing secret.** If `pulso-prod/hackathon` already exists an apply does not touch it. Seed the new keys with `.\scripts\aws-prod.ps1 seed-secret-keys -Profile pulso-prod`: it reads the sensitive output `generated_secrets`, adds only the keys that are missing or still `CHANGE_ME`, keeps every key that holds a value (DB passwords, TOTP key, session secret), prints key names only and asks for the word SEED. Do NOT `terraform apply -replace` the secret version: it resets every out-of-band key to `CHANGE_ME`.
- **Derivation check.** The Ed25519 seed and public key are cut out of the provider's PKCS#8 and SPKI PEM in pure HCL; `generated_credentials.tftest.hcl` pins the result against RFC 8032 test vector 1. Re-run `terraform test` in `terraform/modules/hackathon_data` after any change to `generated.tf`.
