## Simplification decision (supersedes earlier choices for the account that will be created)

Binding input from the owner, recorded here instead of a new ADR because it changes defaults and operator workflow, not the architecture of ADR 0007:

- **One environment, `prod`**, region `us-east-1`, one new AWS account. Name prefix `pulso-prod`, tag `Environment = prod`. The old `staging` and `hackathon` environment names and the `us-east-2` or "no default region" choices no longer apply to this account.
- **No billing alerts, budget or monthly cap**, **no CI/OIDC role**, **no Organizations, no Identity Center** (not free, not needed for one account). The code for the budget, CloudTrail and the GitHub role still exists in `terraform/bootstrap` but is off and requires no input.
- **The human deploys from his machine** with a profile of an admin identity of the new account, using `scripts/aws-prod.ps1` (plan, saved plan, typed confirmation; never auto-approve).
- **Root user for now, IAM admin user later.** The owner chose to start with the root user's access key. Consequences and the three safety rules (MFA on root, key created only in the console and entered only with `aws configure --profile pulso-prod`, delete the key when done) are in [security-model](security-model.md); `aws-prod.ps1 check` warns without blocking. The safer alternative is an IAM user `pulso-admin` with `AdministratorAccess`.
- **Data loading is simple**: the human uploads to `landing/`; the loader runs on the engine host (`engine_host_can_load`, default true); the account's IAM users and root may upload and break glass by default. Core and platform hosts stay denied. There is no attempt to lock data access to one PC.
- **Everything else stays**: three hosts, private subnets, SSM only, deny-only bucket policy, KMS, one secret, WAF toggle, digest-pinned images.

## free_plan profile (record 0008)

Context: the new account is on the AWS Free Plan and the human will not upgrade now. Decision: an additive profile, `profile = "free_plan" | "prod"` (default `free_plan` for now; `prod` keeps the previous design reachable). Differences and why:

- **Compute**: core host `m7i-flex.large` (2 vCPU, 8 GB: core-migrate, runtime, exporter, llm-gateway **and** a Postgres 16 container), platform and engine `t3.small`. `instance_types` is validated against the Free Tier eligible list in this profile. t4g types are arm64 and the images and AMI are x86_64, so they are accepted by the plan but not usable without arm64 images.
- **Database**: `database_mode = "container"` (default in free_plan, `"rds"` in prod; the RDS code is unchanged behind the toggle). Postgres runs in the core compose bundle with its own EBS volume, daily DLM snapshot (same policy as the data volume), `max_connections=40`, init SQL from `terraform/modules/hackathon_data/sql/` run once by `initdb/10_init.sh` (refuses `CHANGE_ME` passwords), and the engine's own migrations afterwards. Platform and engine reach it as `core.<private zone>:5432`; the DSNs still come from the one Secrets Manager secret. Trade-offs: single host, no automated failover, no TLS inside the VPC, recovery is a snapshot restore.
- **Network**: no NAT gateway. Hosts are in the public subnets with public IPs for outbound-only egress; the security groups admit no ingress except the CloudFront origin-facing prefix list on the proxies (80/8080) and sibling security groups to core (8000, 5432). The S3 gateway endpoint stays (it is attached to the public route table too). Isolated db subnets and the db security group exist only in `rds` mode.
- **Edge**: CloudFront with a **public** origin (the host public DNS name). Protection is two layers: the prefix-list security group and the secret header `X-Origin-Verify`, generated by Terraform (stored as `COMMON__ORIGIN_VERIFY` in the one secret), sent by CloudFront and enforced by the Caddy proxies (reject with 403 before any proxying; `/healthz` stays open for the container healthcheck; the host refuses to start a proxy without the value). Note the prefix list is shared by all CloudFront customers, which is why the header matters. WAF is off by default (`enable_waf` null); `edge_enabled = false` brings the stack up without CloudFront.
- **Images**: `image_builder_compute_type` defaults to `BUILD_GENERAL1_SMALL` (3 GB) in free_plan and may run out of memory on the Rust release build. Documented fallback: `scripts/aws-prod.ps1 images -Service <svc> -Builder host` zips the source to S3 as before, then runs `docker buildx build` on the core host through SSM (4 GB swap added on demand), pushes to ECR and writes the same build record. It needs `enable_host_builder` (default on in free_plan), which gives only the core role ECR push and the two `engine/build-*` prefixes.
- **Unknowns**: NAT gateway, RDS, CloudFront, WAF and CodeBuild sizes may also be restricted on the plan; this is only discovered at apply time, hence the staged apply in [operations](operations.md#apply-in-stages-free_plan).

Graduation path to a hardened setup: [security-model](security-model.md#graduation-path-when-this-becomes-more-than-a-hackathon).
