# Open infrastructure gaps

These are external decisions required to apply Terraform, not reasons to
pretend the declared resources are deployed.

| Gap | Owner | Evidence needed | Safe fallback |
|---|---|---|---|
| Account-level GitHub OIDC provider and exact subject claims | Pulso AWS/GitHub administrators | Existing approved `github_oidc_provider_arn` and least-privilege `github_subjects` | No AWS plan/apply; CI remains credential-free validation |
| State bucket/table and bootstrap authority | Pulso AWS administrators | Existing governed state location or authorization for a bootstrap apply | Keep backend examples only |
| VPN/customer-gateway details | Network owner | Customer gateway, routing and approval | No VPN resource or route is created |
| Authenticated or private edge contract for a public HTTP API | improvement-engine and security owners | Published engine listener/health/auth contract plus approved authorizer or private-ingress architecture | No public HTTP API is created; the versioned contract remains non-deploying |
| Alarm destination confirmation | Service owner | Confirmed mailbox/on-call escalation and AWS SNS subscription confirmation | Non-null `alarm_email` creates an email subscription, but no alert is deliverable until its recipient confirms |
| Runtime database role and secret bootstrap | Database/security owners | ECS cannot prove a least-privilege connection to the declared RDS instance | Approved migration creating `pulso_runtime`, least-privilege grants, rotation and an externally managed `runtime_database_secret_arn`; the task must never receive the RDS master secret | Runtime remains dependency_blocked; do not present ECS/RDS declarations as an operable service |
| Runtime secret retrieval path | Network/KMS owners | Terraform alone cannot prove ECS retrieves the role secret | CMK key policy plus approved ECS egress or VPC endpoint path for Secrets Manager/KMS and a redacted smoke | Do not claim an ECS/RDS connection from a validated Terraform graph alone |
| Internal debug-ingress contract | improvement-engine + security + infra | `/internal/v1/debug` cannot be exposed safely | Listener/health/auth contract, internal ALB plus identity-aware proxy decision, private access route and integration tests | Keep the debug service unexposed; no API Gateway placeholder |
| Controlled external egress | Security + model-provider owner + infra | Runtime cannot make a governed external provider call | Versioned `egress_profile`, destination-control/logging approach and failure tests | `aws_private_endpoints_only`; dependency unavailable |
| Engine operational metric/alarm contract | improvement-engine + service owner + infra | AWS alarms beyond resource CPU diagnostics | Metric namespace/dimensions, thresholds, destination/runbook and firing/resolved evidence | Do not call the deployment operationally monitored |
| Agent Core workload apply | infra + agent-core | Declared in Terraform (ADR 0005) and validated with mocks only. Still needed: image CI that publishes a digest to the ECR repository, an ACM certificate, approved `agent_core_ingress_cidrs`, the externally bootstrapped `pulso_runtime`-style application secret for the Agent Core database, and a first reviewed plan | `agent_core_desired_count = 0`; nothing is applied; Agent Core runs locally only |
| Agent Core evaluation database | infra + agent-core | `AGENTCORE_EVAL_DSN` has a secret entry, but no database is declared for it (ADR 0003 open question 1) | Operator-created logical database on the Agent Core instance, or run without `--registry-api` |
| Agent Core event consumers | consuming teams + infra | Real consumers for `agent_core_event_consumers` (handoff router, analytics) and who deduplicates by `event_id`; the chain and registry events are not yet published by the relay (`agent-core` ADR 0023) | No consumer queues (`{}`); events accumulate in the outbox |
| Agent Core blob migration order | agent-core + infra | Enabling `AGENTCORE_BLOB_BUCKET` drops the `reg_blobs` foreign key; `agentcore blobs-backfill` must run before the fallback is removed | Leave the variable unset to keep blobs in PostgreSQL |
| JEV data residency, retention and region | Security/legal + JEV provider | Written answer on where JEV processes and retains data; confirmation or change of the provisional `us-east-1` | Synthetic data only; no customer or bank data reaches JEV |
| Agent Core runtime secrets | Security/KMS owners + agent-core | Secret *entries* are declared and injected per role (ADR 0005); values must be set out of band, and a delivery path is still missing for the public identity-key file and one key per LLM endpoint (`agent_core_extra_secret_names`) | Do not set placeholder values; the task would fail closed |
| Agent Core outside demo mode | agent-core + data/identity teams | Real tools, authorization, transcript, calibration, classifier, field classification and grant checks exist in `agent-core` | Run only with `AGENTCORE_ALLOW_DEMO=1` and synthetic data, and only as the hackathon demo |
| LLM gateway workload declaration | infra + llm-gateway | A published image digest (the `llm-gateway` CI builds the image but does not publish it), the ECR/ECS slice from ADR 0004 and its security group | Nothing is deployed; the gateway runs locally only and Agent Core keeps its own gateway |
| LLM gateway service-to-service ingress | infra + security + consumers | Internal load balancer or service discovery, TLS termination, and an idle timeout above the 300-second maximum call deadline (or consumers capped below the balancer's) | No consumer can reach a deployed gateway; no public route is created |
| LLM gateway secrets | Security/KMS owners + llm-gateway | Secret entries and a delivery path for one Bearer token per consumer and one API key per `LLM_ENDPOINTS` alias | Do not provision or inject placeholders; the service exits non-zero at startup |
