# 0019 the shared Core is agent-core's `agentcore serve` (ADR 0009)

Owner decision: the shared Core is the agent-core repository's own image, not the improvement-engine `core-bridge` composed runtime. Authoring and offline validation only; nothing was planned against AWS or applied.

- Core host bundle: `agentcore migrate` + `agentcore serve --registry-api` (identity-keys and staff-keys documents, real tools, authz, field-classifier and grant-active adapters) + llm-gateway published on 8080; `core-exporter` removed. Field-classification overlay `deploy/hackathon/core/field-overlay.json` (copy of agent-core's e2e overlay) is mounted.
- Image flow: `aws-prod.ps1 images -Service agent-core -AgentCoreDir ... [-AgentCoreCommit ...]` zips the agent-core checkout alone and builds its Dockerfile (CodeBuild or core host), `GIT_SHA` = the pinned commit (HEAD of a clean checkout, or the explicit 40-hex commit). The CodeBuild project for `core-runtime` no longer sets a Dockerfile, context dir or named context; the repository and image key keep their names.
- Terraform (`hackathon_data/generated.tf`): gateway bearer per consumer, grant-check bearer, HMAC key material, four Ed25519 keys; the Core's `identity-keys`/`staff-keys` documents, the platform's `agent-keys` document and the engine's seed are assembled from them and written into the single secret. Ed25519 seed and public key are derived from the provider's PEM in HCL and pinned against RFC 8032 test vector 1. `GATEWAY_CONSUMERS` and `LLM_ENDPOINTS` (alias `openrouter` only) are derived SSM values (moved blocks from the old placeholders).
- Network: core SG 8080 from engine, platform SG 8081 from core (Caddy internal listener limited to `/api/v1/internal/grants/*`), matching egress. Platform backend gets `CC_AGENT_CORE_URL` and `CC_AGENT_KEYS_FILE`; engine gets the gateway and Core addresses and credentials. The start script (`user_data`) is untouched so no instance is replaced: key documents are env values written to `/tmp` by the compose entrypoints.
- Findings that stay open (ADR 0009): agent-core has no real transcript store, calibration source or classifier provider and its image has no `testing` package, so `serve` cannot start outside demo until agent-core ships them (`agent_core_serve_pieces`); no tool service is deployed; no field-grants file; the secret version ignores later changes so an existing secret must be reseeded by hand.
- Validation: `terraform fmt -check -recursive terraform`; `terraform test` in `modules/hackathon_data`, `modules/hackathon_compute`, `modules/hackathon_network` and `envs/hackathon` (mock AWS provider; the env tests run the real `tls`/`random` providers locally); `python -m unittest discover -s tests` (200 + 8 new, all OK); Pester 3.4 `scripts/tests/aws-prod.Tests.ps1` (85 passed). No `terraform plan` against AWS, no apply, no AWS call.
